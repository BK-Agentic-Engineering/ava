## Current direction after Wave 16 (2026-11-06)

The immediate use is to develop a Vietnamese text agent that chooses an authorized action from the request, history, context, permissions and actual observations. Success includes choosing when to ask or only observe, preserving unrelated state, and answering the user when required. The 862 replayed scenarios support local development of this task. Training benefit, deployment prevalence and end-to-end voice performance are open empirical questions. This section sets the order of work for the next waves.

**Design the next wave around a decision that transfers.** For each proposed family, record the intended rule, the shortcut that could pass existing examples, the condition that changes the correct decision, and what evidence the agent can see. ## Lineage and split policy

Assign split before authoring an expansion group. Shared source WORLD, instantiated scenario template, dependency structure plus intended decision logic, counterfactuals, reordering, paraphrases and audio versions retain ancestry and split. All 36 existing scenarios and any descendants remain dev. A new name/ID/room is not an independent construction.

Sharing a tool or broad mechanism alone is not leakage. A separately authored task may qualify as independent if it was not instantiated from an existing WORLD/template, has its own entity relationships and intent/evidence/effect construction, and records source/authoring rationale. Compare task structure and ancestry before labeling it independent; substantive derivatives inherit split even if they add a new combination. Link multiple parents honestly; lineage IDs are bookkeeping, not proof of independent experimental units.

Later evaluation must declare its claim: new WORLD/entity instances within known mechanisms versus new task structures/combinations. Surface-renamed holdouts cannot establish structural generalization. Do not create held-out records here. Later held-out material should be constructed and frozen separately; if used to tune prompts, generation or oracle choices, reclassify the affected ancestry as development and obtain a new holdout. Never hide the reclassification by changing IDs.

## Minimum release-candidate requirements

Before counting a candidate as release/export eligible, require actual contracts/permissions, an executable independently authored fixture, a uniquely justified intent/outcome from permitted information, argument provenance and ordered grounding, positive replay, focused negative checks, unrelated-state/existing-record preservation and accepted valid alternatives. Derive the oracle from user intent and fixture semantics **before** the positive trace; never infer it from one successful execution or copy the implementation under test as semantic gold.

Review semantic uncertainty explicitly or retain it as unresolved. Use simple structural comparison of fixtures, constraints, ancestry and dependency graphs plus targeted text review to distinguish accidental near-duplicates from intentional minimal pairs. No embedding service, automatic hashing, database or large status framework is needed. Record source revision, actual review/replay evidence and integration/export readiness using existing conventions; do not redefine execution_verified or silently promote spec_only.

Keep local goal/frame/ordered-evidence checks separate from official call matching. [Description](../project/description.md), Evaluation: official state-hash agreement and one-to-one call matching are distinct; fuzzy arguments use lowercase/NFC token-F1 > 0.6 and call matching ignores order. The complete official matcher is not provided by the inspected runtime; the local semantic verifier does not claim equivalence. Runtime success or an ask response does not establish official semantic/policy acceptance. No new hashes are needed in this design iteration.

Do not universalize “any failed tool call means task failure.” Preserve every attempt; reject only where the authored goal/frame/trace restrictions justify it. Recovery cases need their own allowed continuation and retry semantics; a failure is not automatically either harmless or fatal. Conditional-OOS and ambiguity probes without resolved policy remain development-only/non-exportable even after local replay. Gold text equivalence beyond explicit reviewed examples stays unresolved until reviewed.
